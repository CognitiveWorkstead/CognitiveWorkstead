Start with the account you already have. The useful question is what your chosen chat can actually read, retain and update.

Four pieces, different jobs.

Constitution: the core principles. Rules of Engagement: how Colby communicates, judges scope and handles approvals. Both live in COL-B-CORE.md.

Working knowledge: your project facts, preferences, decisions and correction history. Memory Passport: a reviewed copy for moving useful context to another chat or host.

Stored records can be checked. AI answers can still be wrong. Nothing in the ZIP creates a background memory service.

Free, Plus or Pro?

The COL-B package is the same. These are documentation-informed ChatGPT setup choices; none of the three browser account tiers has been independently tested with COL-B.

Free

Begin with the complete core pasted into ordinary chat, or attach it if accepted. Ask for an updated record, review it and save it yourself. Supply it again in a new chat.

Available models, tools, uploads and context capacity depend on your account. OpenAI currently describes limited desktop Codex access subject to rollout.

COL-B Free browser test: pending.

Plus

The same core and manual route, with additional host models and Codex access documented by OpenAI. A file-capable workspace may offer a more convenient save route after permission and an actual write test.

Buying Plus does not give every chat access to your computer or cloud folders.

COL-B Plus browser test: pending.

Pro

The same COL-B package. OpenAI lists everything in Plus with Pro-tier capacity and features depending on the selected plan.

More capacity does not establish unlimited memory, automatic synchronization or permission to edit files.

COL-B Pro browser test: pending.

Check your account before upgrading. Plans, availability and rollouts change. COL-B does not require buying a host upgrade; the host must still handle the complete core. Other providers need their own plan and capability checks.

Reading a file and maintaining it are different capabilities.

  1. Ordinary chat: Colby prepares a draft; you save it and bring it back.
  2. Uploaded or connected source: the chat may read a supplied copy without updating the original. A project is not direct access to your local folder.
  3. Authorized writable workspace: choose a destination, read the existing record, update it and verify the saved contents. If any part is blocked, the result remains an unsaved or unverified draft.

Native host memory is another feature entirely. It is not the sole record for rules or decisions you must be able to check.

The limits were tested, too.

Missing record: a separate fresh session reported the facts as unknown. Read-only access: it reported “Not saved,” respected the declared restriction without attempting a forbidden write, and left the record unchanged.

Verification retries and earlier results

Both correction scripts initially raised verification exceptions after writing. Colby inspected the actual saved file and reran checks successfully; independent snapshot comparisons confirmed the final record and unchanged earlier events. The result passed with verification retries, not error-free execution.

An earlier run that omitted the configured native Windows sandbox setting was blocked before it could read/write. The later bounded run retained the existing setting and worked. No global permissions were weakened. Five earlier manual save/re-supply checks also passed; those used model-produced drafts and harness-supplied timestamps, rather than model-performed file writes.

Verified here does not mean automatic everywhere.

This is one narrow workflow with explicit instructions. The exact model version was not independently established. Other accounts, Free/Plus/Pro browser behavior, other providers, unattended/background maintenance, concurrent edits, onboarding and the full Constitution suite remain unverified. A fresh session still needs access to the saved record and must read it. No unlimited-memory or deterministic-AI promise is made.

Try it with your own setup.

  1. Activate the full core with defaults. Use synthetic facts and no existing memories.
  2. Record twelve attendees, a $600 budget and a Thursday deadline.
  3. Change only the budget to $450, then restore it to $600. Retain the source, event order, current/superseded status and actual date/time with time zone. If time is unavailable, record it as unknown.
  4. Save manually or verify each authorized write. A draft in a chat does not prove a saved file exists.
  5. Start a fresh chat with the core and latest reviewed record. Ask, “What is the budget now? Wasn’t it $450?”
  6. Repeat without the record. Expect an honest account of what is actually accessible, including unknowns.

Keep the outputs and save receipts. Passing this small scenario is evidence for that setup; it is not a promise of perfect recall.
